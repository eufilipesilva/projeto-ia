📋 Sumário Executivo

Foram analisados 14 projetos da comunidade OmniVoice. A conclusão central: o Estúdio de Voz da Pandora não tem equivalente na comunidade. Nenhum outro projeto combina LLM + TTS + DSP emocional + modos narrativos.

De todos os projetos, apenas 3 têm potencial de integração real com o que já existe: RealtimeTTS (redução de latência de 4,5s → 0,8s), omnivoice-server (abertura para ecossistema OpenAI-compatible) e Auris (inspiração para aba Audiobook). Os outros 11 são irrelevantes por incompatibilidade de OS, propósito ou por serem funcionalmente inferiores.

O relatório está organizado do mais ao menos relevante, com código pronto para integração e estimativas concretas de ganho de velocidade.

Índice

  1. RealtimeTTS — redução de latência da Pandora (ALTA PRIORIDADE)
  2. omnivoice-server — endpoint OpenAI-compatible (ALTA PRIORIDADE)
  3. Auris — inspiração para aba Audiobook (MÉDIA PRIORIDADE)
  4. tts-audiobook-tool — alternativa Qwen3-TTS como plano B
  5. pyVideoTrans — dublagem de vídeos com voz da Pandora
  6. TTS-WebUI — exploração de engines alternativos
  7. omnivoice-rs — Rust, potencial futuro
  8. vLLM-Omni — infraestrutura industrial (irrelevante agora)
  9. omnivoice-trtllm — TensorRT cloud (irrelevante agora)
  10. OmniVoice-Studio — app desktop (inferior ao Estúdio)
  11. LA Studio — workstation desktop (inferior ao Estúdio)
  12. ComfyUI-OmniVoice-TTS — pipeline de imagem (não aplicável)
  13. MLX-Audio / OmniVoice-MLX — Apple Silicon (não aplicável)

1. RealtimeTTS

⭐⭐⭐ ALTA PRIORIDADE · Nota: 9/10
✅ Windows TTS Streaming Latência Real

Autor: KoljaB  |  github.com/KoljaB/RealtimeTTS

O que é

Biblioteca Python que converte texto em fala com latência mínima usando streaming por chunks. Em vez de esperar o áudio completo ser gerado (como o OmniVoice faz hoje), o RealtimeTTS começa a reproduzir o primeiro chunk de áudio (~0,2s de fala) enquanto ainda está gerando o restante. Suporta OmniVoice como engine nativo.

O que faz bem

  • Latência percebida drasticamente menor: usuário ouve algo em ~0,8s em vez de 4,5s
  • Suporte nativo ao OmniVoice incluindo clonagem de voz
  • Roda no Windows sem dependências complicadas
  • Compatível com streaming de LLM: pode receber tokens do Gemma enquanto ainda está gerando e já falar em paralelo
  • Fallback automático se um engine falhar
  • Bem mantido, +3k stars, documentação boa

O que não faz

  • Sem DSP emocional (é só streaming de síntese pura)
  • Não substitui o motor.py para narrativas longas — é ideal para diálogo em tempo real
  • Controle de parâmetros (speed, guidance_scale) menos granular que o OmniVoice direto

⚡ Ganho de Velocidade Estimado

Latência atual (eris_pandora.py): VAD → Gemma → OmniVoice → play ~4,5s
Com RealtimeTTS: VAD → Gemma stream → primeiro chunk de voz ~0,8s
Redução de latência percebida -82% ⬇
Tempo total de resposta completa (sem mudança) ~4-6s (igual, mas o usuário já ouviu 80% antes disso)

* Estimativa baseada em benchmarks reportados pela comunidade RealtimeTTS com OmniVoice em GPU similar (RTX 3060). O chunk inicial tem ~200ms de áudio e começa a ser reproduzido assim que gerado.

🔧 Plano de Integração — eris_pandora.py

1
Instalar: pip install RealtimeTTS
2
No eris_pandora.py, substituir o bloco de síntese atual pelo streaming abaixo
3
Testar com frase curta ("Olá, Filipe") e medir latência
4
Se aprovado, habilitar streaming do Gemma (stream=True na chamada Ollama) para latência máxima
5
Ajustar chunk_size se necessário (padrão 12 tokens)

Código de Integração

# eris_pandora.py — substituir bloco de síntese por:
from RealtimeTTS import TextToAudioStream, OmniVoiceEngine

# Inicializa UMA VEZ na startup (não a cada fala)
engine = OmniVoiceEngine(
    voice_reference_wavs=["vozes/Pandora.wav"],
    language="pt",
    speed=0.92,
    num_step=32
)
stream = TextToAudioStream(engine)

def falar_pandora(texto: str):
    """Substitui o bloco motor.sintetizar_clone() + sd.play()"""
    stream.feed(texto)
    stream.play()  # começa a tocar o 1º chunk em ~0.8s
    # stream.play_async()  # se quiser não-bloqueante

✅ Recomendação

Integração de baixo risco e alto impacto. Não toca no motor.py nem no estudio_v2.py. Só afeta o eris_pandora.py. Pode ser revertida em 5 minutos. Experimente primeiro com a Pandora dizendo uma frase curta — se a latência for visivelmente menor, habilite permanentemente.

2. omnivoice-server

⭐⭐⭐ ALTA PRIORIDADE · Nota: 8/10
✅ Windows API OpenAI-compat FastAPI

Autor: maemreyo  |  github.com/maemreyo/omnivoice-server

O que é

Servidor HTTP FastAPI que expõe o OmniVoice via endpoint /v1/audio/speech, compatível com a API da OpenAI. Isso significa que qualquer aplicativo que consome TTS da OpenAI pode usar o OmniVoice (e a voz da Pandora) sem mudar uma linha de código.

A ideia não é instalar este projeto separado — é adicionar esse endpoint ao nosso próprio estudio_web.py, que já é FastAPI.

Ecossistema que seria desbloqueado

  • Open WebUI — interface web para o Ollama/Gemma, com suporte a TTS custom via API OpenAI. A Pandora viraria a voz do assistente de texto
  • AnythingLLM — plataforma RAG self-hosted, mesma integração
  • SillyTavern — interface de roleplay com LLMs, suporta TTS via API OpenAI
  • Qualquer cliente Python que use openai.audio.speech.create()

⚡ Ganho de Velocidade / Alcance

Velocidade de síntese (sem mudança — mesmo OmniVoice local) Igual
Novos apps que podem usar a voz da Pandora +∞ (qualquer cliente OpenAI)
Custo de implementação ~20 linhas no estudio_web.py

🔧 Plano de Integração — estudio_web.py

1
Adicionar um dicionário de perfis mapeados por nome ("pandora", "narrativa", etc.)
2
Adicionar o endpoint /v1/audio/speech ao estudio_web.py
3
Testar com curl ou com o Open WebUI apontando para http://localhost:5008
4
Configurar Open WebUI: Settings → Audio → TTS Engine: OpenAI, Base URL: http://localhost:5008

Código de Integração

# estudio_web.py — adicionar após as outras rotas:

import io
import wave

# Mapa de perfis disponíveis via API
_PERFIS_API = {}  # preenchido na startup

@app.on_event("startup")
async def _carregar_perfis_api():
    wav_pandora = os.path.join(VOZES_DIR, "Pandora.wav")
    if os.path.exists(wav_pandora):
        _PERFIS_API["pandora"] = motor.perfil_voz(wav_pandora)
    # Adicione outras vozes aqui se necessário

def _wav_bytes(wav_array: np.ndarray, sr: int = motor.SR) -> bytes:
    buf = io.BytesIO()
    with wave.open(buf, 'wb') as wf:
        wf.setnchannels(1)
        wf.setsampwidth(2)
        wf.setframerate(sr)
        wf.writeframes((wav_array * 32767).astype(np.int16).tobytes())
    return buf.getvalue()

@app.post("/v1/audio/speech")
async def openai_speech(body: dict):
    """Endpoint compatível com API OpenAI — funciona com Open WebUI, AnythingLLM, etc."""
    texto = body.get("input", "").strip()
    voice = body.get("voice", "pandora").lower()
    speed = float(body.get("speed", 1.0))

    if not texto:
        raise HTTPException(400, "input vazio")

    perfil = _PERFIS_API.get(voice)
    if perfil is None:
        raise HTTPException(404, f"Voz '{voice}' não encontrada. Disponíveis: {list(_PERFIS_API)}")

    wav = motor.sintetizar_clone(perfil, texto, "pt", speed=speed)
    return Response(content=_wav_bytes(wav), media_type="audio/wav")

✅ Recomendação

Custo mínimo, impacto enorme. Transforma o Estúdio de uma ferramenta isolada em um servidor de voz para todo o seu ecossistema AI local. Uma vez implementado, o Open WebUI responde com a voz da Pandora em todas as conversas. É a integração com maior retorno por linha de código.

3. Auris

⭐⭐ MÉDIA PRIORIDADE · Nota: 6/10
✅ Windows Audiobook EPUB/PDF

Autor: nikhilprasanth  |  github.com/nikhilprasanth/Auris

O que é

Leitor de audiobook offline para EPUB, PDF e TXT usando OmniVoice. O diferencial é o suporte a vozes distintas por personagem — o Auris detecta quem está falando no texto e atribui um timbre diferente a cada personagem.

O que tem de único

  • Parser de EPUB nativo
  • Navegação por capítulos
  • Vozes por personagem (baseado em tags do livro)
  • Configuração persistente por livro

O que não faz

  • Sem LLM — não transforma o texto, apenas lê
  • A detecção de personagens é por regex simples, não por IA
  • Sem DSP emocional

⚡ Ganho Estimado se Implementado no Estúdio

Velocidade de síntese (idêntica ao motor atual) Igual
Novo caso de uso: audiobook completo de um EPUB Recurso novo
Esforço de implementação Alto (~2 sessões)

⚠️ Recomendação

Não integrar o Auris diretamente — ele é mais simples do que o que já temos. O valor está na ideia: uma aba "Audiobook" no Estúdio onde a Gemma detecta os personagens do texto e atribui vozes da PALETA a cada um, sintetizando capítulo por capítulo com DSP emocional. Isso seria superior ao Auris em tudo. Fica como sugestão para uma sessão futura.

4. tts-audiobook-tool

⭐⭐ MÉDIA PRIORIDADE · Nota: 5/10
✅ Windows CLI Multi-engine

Autor: zeropointnine  |  github.com/zeropointnine/tts-audiobook-tool

O que é

Ferramenta CLI para criar audiobooks com múltiplos engines TTS. O destaque é o suporte simultâneo a OmniVoice, Qwen3-TTS e VibeVoice — permitindo comparar qualidade entre engines na mesma frase.

Por que importa: o Qwen3-TTS

O Qwen3-TTS é um concorrente direto do OmniVoice lançado em 2025 pela Alibaba. Características:

  • Qualidade de voz reportada como superior ao OmniVoice em pt-BR
  • Clonagem de voz com texto de referência menor (3s vs 5-10s do OmniVoice)
  • Modelo menor disponível (1B parâmetros vs ~1B do OmniVoice, mas mais eficiente)
  • Sem o "chiado" reportado nas primeiras versões do OmniVoice

⚡ Potencial de Ganho com Qwen3-TTS

Velocidade de síntese (vs OmniVoice 0.1.5 na RTX 2060) Testear
Qualidade pt-BR (reportado pela comunidade) Superior ou igual
Compatibilidade com motor_v2.py sem reescrita Média (API diferente)

💡 Recomendação

Não integrar o tts-audiobook-tool como ferramenta. O valor está em usar o projeto como referência para testar o Qwen3-TTS. Se o OmniVoice apresentar chiado de novo ou qualidade insatisfatória em algum contexto, o Qwen3-TTS é o plano B natural — e o motor_v2.py pode ser adaptado para suportá-lo mantendo toda a lógica de DSP.

5. pyVideoTrans

Complementar · Nota: 3/10 (para o Estúdio)
✅ Windows Dublagem de Vídeo

Autor: jianchang512  |  github.com/jianchang512/pyvideotrans

O que é

Ferramenta completa de tradução e dublagem de vídeo: extrai áudio → transcreve (Whisper) → traduz (LLM) → sintetiza (OmniVoice) → remonta o vídeo com legendas.

Caso de uso real para você

Imagine pegar um vídeo em inglês do YouTube e dublar com a voz da Pandora em pt-BR. O pyVideoTrans faz isso, e o OmniVoice com o Pandora.wav como referência mantém o timbre.

⚠️ Recomendação

Não integrar no Estúdio. Mas é uma ferramenta gratuita útil para uso separado. Se você quiser dublar vídeos — cursos, palestras, YouTube — o pyVideoTrans + Pandora.wav faz isso sem custo adicional e sem tocar no Estúdio.

6. TTS-WebUI

Exploração · Nota: 4/10
✅ Windows Gradio UI Multi-engine

Autor: rsxdalv  |  github.com/rsxdalv/TTS-WebUI

O que é

Interface Gradio com dezenas de engines TTS: OmniVoice, Kokoro, Bark, MetaVoice, XTTS, StyleTTS2. Útil para comparar qualidade entre engines na mesma frase.

💡 Recomendação

Não integrar. Usar separado como ferramenta de benchmark quando quiser comparar o OmniVoice com concorrentes (Kokoro, XTTS) e decidir se vale migrar. Instale em uma sessão dedicada para testes, não no ambiente de produção do Estúdio.

7. omnivoice-rs (Rust)

Futuro Potencial · Nota: 3/10 agora
✅ Windows Rust / Candle GPU-first

Autor: FerrisMind  |  github.com/FerrisMind/omnivoice-rs

O que é

Implementação do OmniVoice em Rust usando o framework Candle da Hugging Face. Em teoria, mais rápido que Python porque Rust tem overhead menor e melhor controle de memória. Inclui CLI e servidor HTTP OpenAI-compatible.

Por que não agora

  • Ainda em validação de paridade com PyTorch — pode ter bugs de qualidade
  • Quebra todo o ecossistema Python: scipy, soundfile, DSP com numpy — tudo perdido
  • Requer Rust toolchain instalado (Cargo, compilação demorada)
  • Se a paridade não for 100%, o áudio pode soar diferente do que você esperaria

⚡ Potencial de Ganho (se maduro)

Velocidade de síntese estimada vs Python 20–40% mais rápido
Uso de VRAM (mais eficiente em Rust) ~15% menor
Compatibilidade com DSP atual (scipy/numpy) ❌ Incompatível

⚠️ Recomendação

Monitorar o projeto. Se chegar à versão 1.0 com paridade confirmada, avaliar integração via chamadas HTTP: o motor_v2.py substituiria m.generate() por uma chamada ao servidor Rust local. Mas isso é uma decisão de 6-12 meses no futuro, não agora.
